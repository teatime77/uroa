# diagramのESP32 BLE／Wi-Fi接続画面

更新日: 2026-10-15。現在の画面の説明と操作手順。今ある入力欄とボタンの使い方をまとめる。

初回はBLEでESP32へ接続し、Wi-FiのSSIDとパスワードを設定する。次回は保存した接続先と接続キーを使い、Wi-Fiから直接接続する。XIAO ESP32S3 SenseとDevKit V1で設定手順は共通で、カメラはXIAOだけが対象。

## 最初に読むこと

初回にユーザーが入力するのは、主に**Wi-FiルーターのSSIDとパスワード**。上段の「接続キーの識別名」と「Wi-Fi接続キー」は、BLE接続後にESP32から自動取得する。初回は「保存済み機器を選択」を操作する必要はない。

画面で扱う3種類のコード・パスワードは、それぞれ用途が違う。

| 名前 | 用途 | 入手先・入力場所 |
|---|---|---|
| BLEペアリングコード | PC／AndroidとESP32のBLE接続を認証する6桁の数字 | ESP32のSerial Monitorで確認し、OSのBluetooth入力画面へ入力する |
| Wi-Fiパスワード | ESP32をWi-Fiルーターや携帯のテザリングへ接続する | ルーターやテザリングの設定で確認し、下段の「Wi-Fiパスワード」へ入力する |
| Wi-Fi接続キー | diagramがWi-Fi経由でESP32を操作するための基板固有のキー | 初回はBLEで自動取得し、上段の「Wi-Fi接続キー」へ入る。次回はChromeの自動入力または手入力を使う |

Gemini APIキーはAIChatBlockの別の設定。上の3項目には入力せず、ESP32へ送ることもない。

## 接続前の準備

- 対象のファームウェアをESP32へ書き込んでおく。XIAOはPlatformIO環境`xiao_esp32s3`、今回のUSBポートはCOM4。書き込み時にはSerial Monitorを閉じる。[ファームウェアの操作手順](../esp32-ble-lab/README.md)を参照する。
- diagramをChromeで開く。PCのローカル開発では、uroaルートで`npm.cmd run dev`を実行し、`http://localhost:5173/diagram/index.html`を開く。Androidなどから使う場合はHTTPSとブラウザーの対応が必要。
- XIAOが接続するWi-Fiは2.4GHzを使う。PCが同じルーターの5GHzへ接続していても、同じLAN内で端末同士が通信できれば利用できる。ゲストネットワークや端末分離の設定では通信できない場合がある。[XIAOのWi-Fi仕様](https://wiki.seeedstudio.com/xiao_esp32s3_wifi_usage/)を参照する。
- 初回のBLEペアリングに備え、Serial Monitorを115200bpsで開く。XIAOの付属アンテナも接続しておく。

## 1. キャンバス上の接続ブロック

左のBluetoothアイコン（`BLEConnectionBlock`）をキャンバスへドラッグする。ブロックを置いただけでは接続しない。接続操作にStartボタンは不要。

| 表示・ボタン | 意味 |
|---|---|
| 「BLE接続」／「Wi-Fi接続」 | 現在使っている通信方式。Wi-Fiへの切り替えが成功すると見出しが「Wi-Fi接続」になる |
| 状態 | 「未接続」「機器を選択してください」「接続中」「接続済み」「接続失敗」「利用不可」のいずれか |
| 端末 | 接続したESP32の表示名。複数基板で同じ表示名になることもあるが、Wi-Fiの登録は基板固有IDで区別する |
| 「接続」／「再接続」 | ChromeのBLE機器選択画面を開き、選んだ機器へBLEで接続する。Wi-Fiへ直接接続する場合は下の「Wi-Fi設定／接続」を使う |
| 「切断」 | 現在のBLEまたはWi-Fiの制御接続を切断する。登録済みの接続先やESP32の保存済みWi-Fi設定は消さない |
| 「Wi-Fi設定／接続」 | 「ESP32のWi-Fi接続」画面を開く。BLE接続中なら初回設定・再設定もでき、BLE未接続なら保存済み機器へWi-Fiで接続する画面になる |

接続処理中はボタンが無効になる。**Wi-Fi接続中も「Wi-Fi設定／接続」は無効**になる。Wi-Fiルーターの変更などを行う場合は、まず「切断」を押してBLEから接続し直す。

## 2. OSのBluetoothペアリング画面

Wi-Fi設定の読み書きを始める際に、OSの「Device Credentials」などの画面が開き、Bluetooth Passkeyの入力を求められることがある。

Serial Monitorの次の行にある6桁の数字を入力する。`XXXXXX`は説明用の表記で、実際には数字が表示される。

```text
BLE connected
BLE setup pairing code: XXXXXX
```

コードはESP32の再起動ごとに生成する。BLE開始時と接続時に表示するので、起動ログを見逃した場合もMonitorを開いたままBLEへ再接続すれば確認できる。すでにペアリング済みなら、入力画面が出ないこともある。

この画面にはルーターのWi-Fiパスワードや、長いWi-Fi接続キーを入力しない。

## 3. 「ESP32のWi-Fi接続」画面の上段

上段は**diagramからESP32へ制御接続するための設定**。初回のBLE接続後には基板の情報と接続キーが自動で入る。ESP32がまだルーターへ接続していない場合は、下段の設定を先に行う。

| 項目・ボタン | 説明・操作 |
|---|---|
| 保存済み機器を選択 | このブラウザーに登録した機器を選ぶ。表示は機器名とmDNS名。主に次回の接続で使う。選び直すと接続キー欄が空になるので、その機器のキーをChromeの自動入力などで入れる |
| 接続キーの識別名 | `robot:uroa-xxxxxxxxxxxx`のようなChrome保存用の識別名。基板IDから自動設定され、読み取り専用。`x`は説明用で、実際は基板ごとの値 |
| Wi-Fi接続キー | ESP32が生成する64文字のキー。初回は自動取得した値を使う。次回はその基板のキーをChromeの自動入力から選ぶか、手入力する |
| 接続成功後、Chromeへ接続キーの保存を要求する | チェックすると、制御接続の成功後にキーの保存をChromeへ要求する。保存確認が出たらChrome側で承認する |
| 保存済みWi-Fiへ接続 | すでにルーターへWi-Fi接続しているESP32に対し、上のキーでdiagramの制御接続を確認する。SSIDやルーターのパスワードを送るボタンではない |
| 接続キーの表示／非表示 | 上段のキーを文字として表示するか、伏せ字にするかを切り替える |
| 選択した機器をこのブラウザーから削除 | ブラウザー内の接続先の登録を削除する。ESP32内のWi-Fi設定と、Chromeのパスワードマネージャーに保存したキーは残る |

## 4. 下段の「アクセスポイントを設定する」

下段は**ESP32をWi-Fiルーターや携帯のテザリングへ接続するための設定**。BLEでESP32へ接続した状態で開いた場合にだけ表示される。

| 項目・ボタン | 説明・操作 |
|---|---|
| Wi-Fiを検索 | ESP32の周囲にある2.4GHz Wi-Fiを検索する。PC側の現在のSSIDを自動取得する機能ではない |
| SSIDを手入力／検索結果の一覧 | 検索結果からSSIDを選ぶ。見つからない場合は「SSIDを手入力」を選び、その下の欄へ名前を入力する |
| SSID（2.4GHz）の欄 | ESP32が接続するネットワーク名。大文字・小文字・空白も含めて正確に指定する |
| SSID直下の`wifi:SSID名`の欄 | ChromeへWi-Fiパスワードを保存するための識別名。SSIDから自動生成され、読み取り専用。ルーターへ送るユーザー名ではない |
| Wi-Fiパスワード | 選んだSSIDのルーター／テザリングのパスワード。上段の接続キーとは別。SSIDを入力・選択し直すとこの欄は空になる |
| パスワードなしのネットワーク | パスワード不要のWi-Fiを使うときだけチェックする。パスワード欄は空になり、入力できなくなる。検索結果がオープンネットワークなら自動でチェックされる |
| ChromeへWi-Fiパスワードの保存を要求する | 接続成功後、ルーターのパスワードを`wifi:SSID名`の識別名でChromeへ保存要求する。上段の接続キーとは別の保存項目 |
| XIAOに設定してWi-Fiへ切り替え | SSIDとパスワードをBLEでESP32へ送り、Wi-Fi接続・保存を待ったあと、diagramもWi-Fiの制御接続へ切り替える。ボタン名はXIAOだが、DevKit V1でも同じ操作 |
| ESP32の保存済みWi-Fi設定を消去 | ESP32内のSSID・パスワードを消去し、ESP32をルーターから切断する。基板ID・接続キー、ブラウザーの接続先、Chromeの保存項目は残る |

現在の入力制限はSSIDが1～32バイト、パスワードが8～63バイト。パスワード不要の場合はチェック欄で指定する。バイト数は文字数と異なり、日本語などは1文字で複数バイトになる。

## 5. 初回の操作手順

1. ESP32を起動し、PC／Androidを同じLANで通信できるWi-Fiへ接続する。
2. diagramの接続ブロックで「接続」を押し、Chromeの機器選択画面から対象ESP32を選ぶ。
3. ブロックが「BLE接続」「状態：接続済み」になったら「Wi-Fi設定／接続」を押す。
4. OSがペアリングコードを要求した場合は、Serial Monitorの6桁を入力する。
5. 上段の識別名と接続キーが自動取得されるまで待つ。初回は保存済み機器を選ばず、取得したキーを使う。
6. 下段の「Wi-Fiを検索」を押してSSIDを選ぶか、SSIDを手入力する。
7. 下段へルーターのパスワードを入力する。Chromeへ保存したい場合は、上段・下段の保存チェックをそれぞれ付ける。
8. **下段の「XIAOに設定してWi-Fiへ切り替え」**を押して待つ。設定・接続の成功後に画面が閉じ、接続ブロックが「Wi-Fi接続」「状態：接続済み」になることを確認する。
9. Chromeが保存確認を表示した場合は、必要な保存項目を承認する。

ESP32はWi-Fi接続とサーバー開始の成功後にSSID・パスワードを保存する。失敗時は以前の保存値を上書きしない。diagramは制御接続の確認成功後に、基板ID・mDNS名・IPなどの接続先をブラウザーへ登録する。

BLEからWi-Fiへ切り替える際はサーボとIMU通知を一度停止し、Wi-Fi制御接続の確立後にBLEを停止する。IMUBlockがあれば通知を再開する。サーボは自動有効化せず、改めて「90°で有効化」を押す。

## 6. 次回からの操作手順

1. ESP32を起動する。保存済みSSID・パスワードでルーターへ接続するので、しばらく待つ。
2. diagramに接続ブロックを配置し、**BLEの「接続」を押さずに「Wi-Fi設定／接続」**を押す。この場合は上段だけの画面になる。
3. 保存済み機器を選ぶ。最初の機器が選択されている場合も、目的の基板か確認する。
4. その機器の`robot:基板ID`に対応する接続キーをChromeの自動入力から選ぶか、手入力する。
5. **上段の「保存済みWi-Fiへ接続」**を押す。画面が閉じ、接続ブロックが「Wi-Fi接続」「状態：接続済み」になれば完了。

SSIDとルーターのパスワードを入力し直す必要はない。図の読込やブロック配置だけでは自動接続しない。接続先はmDNS名を先に試し、失敗時は保存済みIPを試すので、通常はIPを手入力する必要もない。

接続キーをChromeへ保存できなかった場合は、BLEから画面を開き直して再取得できる。ルーター変更、ESP32の保存設定消去、IP変更などで接続できない場合も、BLEから設定・接続先を確認し直す。

## 7. 保存場所と削除の違い

| 保存場所 | 保存する内容 | 消す操作 |
|---|---|---|
| ESP32の不揮発性メモリ | SSID・Wi-Fiパスワード、基板ID・接続キー | 「ESP32の保存済みWi-Fi設定を消去」はSSID・パスワードだけを消す |
| このブラウザーのlocalStorage | 基板ID・表示名・mDNS名・IP・ポート・カメラ対応の情報 | 「選択した機器をこのブラウザーから削除」でその接続先を消す |
| Chromeのパスワードマネージャー | 保存を承認したWi-Fi接続キーとWi-Fiパスワード。それぞれ`robot:基板ID`と`wifi:SSID名`で区別する | Chromeのパスワードマネージャーで対象項目を削除する |

Chrome保存のチェックを外しても、ESP32へのWi-Fi設定保存とブラウザーへの接続先登録は行う。チェック欄はChromeへのパスワード保存要求だけを制御する。

図のDownload・コピー・JSONには、Wi-Fiパスワードと接続キーを含めない。localStorageにもこの2つの秘密情報は保存しない。Chromeの保存・自動入力はChrome側の判断や設定に依存し、チェックだけで保存成功を保証するものではない。

ブラウザーの接続先はオリジンごとに保存される。例えば`localhost:5173`と`127.0.0.1:5173`、別ポート、公開HTTPSのページは別の保存先なので、次回も同じURLで開くと扱いやすい。別のURLやChromeプロファイルを使う場合は、BLEから登録し直す。

## 8. 閉じる・切断・設定変更

「閉じる」またはEscapeは設定画面を閉じ、画面内の入力値とブラウザー側の待機を解除する。保存済み設定は削除しない。ESP32へ送信済みのWi-Fi設定は、画面を閉じてもESP32側で処理が続く場合がある。

BLE接続中に設定画面を開くと、サーボを停止しIMU通知を一時停止する。Wi-Fiへ切り替えず閉じた場合はBLEの通信とIMU通知を再開するが、サーボは自動有効化しない。

ルーターのSSIDやパスワードを変える場合は、接続ブロックの「切断」を押し、BLEから再接続して下段で再設定する。新しいWi-Fi接続に成功すれば保存値を置き換えるため、変更だけなら先に保存済み設定を消す必要はない。

現在はdiagramのタブが非表示になるとBLE／Wi-Fiの制御接続を切断する。別タブへの切り替えやウィンドウの最小化後は、必要に応じて再接続する。Clearや図の読込、ページを離れる操作でも接続を解除する。ESP32は制御接続終了後に復旧用BLEを再開し、再起動時にもBLEを有効にする。

## 9. 表示から次の操作を判断する

| 表示・状況 | 次の操作 |
|---|---|
| 初回のSSID・パスワードを設定してください。 | 下段でSSID・ルーターのパスワードを指定し、「XIAOに設定してWi-Fiへ切り替え」を押す |
| 保存済みWi-Fiへ接続済みです。上のボタンで制御接続を確認できます。 | ESP32はルーターへ接続済み。上段のキーを確認して「保存済みWi-Fiへ接続」を押す。diagramの制御接続はまだ完了していない |
| 下段のアクセスポイント設定がない | BLE未接続で開いた画面。初回設定・再設定をするなら、いったん閉じてBLEへ接続してから開き直す |
| Wi-Fi設定を開けません。対応するファームウェアとBLE接続を確認してください。 | 対象ESP32のファームウェアとBLE接続を確認する。Wi-Fi接続中ならいったん切断する |
| 接続キーが空、または機器の接続キーを取得できません。 | 次回接続なら機器に対応するChromeのキーを選ぶ。初回ならBLEペアリング・Serial Monitorのコードを確認して開き直す |
| Wi-Fi接続が時間切れ、またはWi-Fi設定に失敗 | 2.4GHzのSSIDとそのパスワードを確認する。ESP32へアンテナが接続されているかも確認する |
| Wi-Fiの応答が途切れました。再接続してください。 | diagramとESP32のネットワーク、別タブへの移動などによる切断を確認し、再接続する |
| Wi-Fi接続中で「Wi-Fi設定／接続」を押せない | 設定を変更する場合は「切断」後にBLEから再接続する |

Wi-Fiの制御接続が成功したらCameraBlockを配置すると画像取得が始まる。Startや他ブロックとの配線は不要。現在の取得ループの追加待ちは0msで、実際の更新間隔は撮影・通信・画像読み込みなどの時間に依存する。
