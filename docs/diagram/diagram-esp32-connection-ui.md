# diagramのESP32 BLE／Wi-Fi接続画面

更新日: 2026-10-30。現在の画面の説明と操作手順。今ある入力欄とボタンの使い方をまとめる。現行ファームウェアは別リポジトリーの[diagram-control](../../../esp32/app/diagram-control/README.md)。uroa内の旧ESP32フォルダーは廃止対象。作業先と通信仕様は[ESP32連携ガイド](esp32-integration.md)を参照する。

初回・次回ともBLEでESP32へ接続し、Wi-FiのSSIDとパスワードを入力して「Wi-Fiへ接続」を押す。保存済み機器の選択は行わない。Wi-Fi接続キーは教材用の共通固定値を自動使用する。XIAO ESP32-S3 Sense・DevKit V1・SuperMiniで設定手順は共通で、カメラはSenseだけが対象。

## 最初に読むこと

設定画面にユーザーが入力するのは、**Wi-FiルーターのSSIDとパスワード**。BLE接続中の基板を自動的に対象とする。保存済み機器の選択欄・削除ボタン・専用接続ボタンと、Wi-Fi接続キーの入力欄・Chrome保存要求は削除済み。固定キーに対応したファームウェアをESP32へ再Uploadする必要がある。機器選択画面の削除はWeb側だけの変更。

画面で扱う3種類のコード・パスワードは、それぞれ用途が違う。

| 名前 | 用途 | 入手先・入力場所 |
|---|---|---|
| BLEペアリングコード | PC／AndroidとESP32のBLE接続を認証する教材用の6桁固定値 | OSのBluetooth入力画面へ`123456`を入力する。Serial Monitorでの確認は不要 |
| Wi-Fiパスワード | ESP32をWi-Fiルーターや携帯のテザリングへ接続する | ルーターやテザリングの設定で確認し、「Wi-Fiパスワード」へ入力する |
| Wi-Fi接続キー | diagramがWi-Fi経由でESP32を操作するときの署名計算に使う教材用共通固定値 | diagramとファームウェアに定義済み。初回・次回とも入力・Chrome保存は不要 |

Gemini APIキーはAIChatBlockの別の設定。上の3項目には入力せず、ESP32へ送ることもない。

## 接続前の準備

- 別リポジトリーのdiagram-controlをESP32へ書き込んでおく。PlatformIO環境はXIAOが`xiao_esp32s3`、DevKitが`esp32dev`、SuperMiniが`supermini_esp32s3`。COMポートは実際の接続先を指定する。書き込み時にはSerial Monitorを閉じる。[現行ファームウェアの操作手順](../../../esp32/app/diagram-control/README.md)を参照する。BLE機器選択では通常`ESP32-Diagram-Control`を選ぶ。
- diagramをChromeで開く。PCのローカル開発では、uroaルートで`npm.cmd run dev`を実行し、`http://localhost:5173/diagram/index.html`を開く。Androidなどから使う場合はHTTPSとブラウザーの対応が必要。
- XIAOが接続するWi-Fiは2.4GHzを使う。PCが同じルーターの5GHzへ接続していても、同じLAN内で端末同士が通信できれば利用できる。ゲストネットワークや端末分離の設定では通信できない場合がある。[XIAOのWi-Fi仕様](https://wiki.seeedstudio.com/xiao_esp32s3_wifi_usage/)を参照する。
- 初回のBLEペアリングには固定コード`123456`を使う。診断でログが必要な場合はSerial Monitorを115200bpsで開く。XIAOの付属アンテナも接続しておく。

## 1. キャンバス上の接続ブロック

左のBluetoothアイコン（`BLEConnectionBlock`）をキャンバスへドラッグする。ブロックを置いただけでは接続しない。接続操作にStartボタンは不要。

| 表示・ボタン | 意味 |
|---|---|
| 「BLE接続」／「Wi-Fi接続」 | 現在使っている通信方式。Wi-Fiへの切り替えが成功すると見出しが「Wi-Fi接続」になる |
| 状態 | 「未接続」「機器を選択してください」「接続中」「接続済み」「接続失敗」「利用不可」のいずれか |
| 端末 | 接続したESP32の表示名。複数基板で同じ表示名になることもあるが、Wi-Fiの登録は基板固有IDで区別する |
| 「接続」／「再接続」 | ChromeのBLE機器選択画面を開き、選んだ機器へBLEで接続する。Wi-Fiへ直接接続する場合は下の「Wi-Fi設定／接続」を使う |
| 「切断」 | 現在のBLEまたはWi-Fiの制御接続を切断する。ESP32の保存済みWi-Fi設定は消さない |
| 「Wi-Fi設定／接続」 | BLE接続中のESP32へ送るWi-Fi設定画面を開く。BLE未接続の場合は、先に「接続」でBLE接続する案内を表示する |

接続処理中はボタンが無効になる。**Wi-Fi接続中も「Wi-Fi設定／接続」は無効**になる。Wi-Fiルーターの変更などを行う場合は、まず「切断」を押してBLEから接続し直す。

## 2. OSのBluetoothペアリング画面

Wi-Fi設定の読み書きを始める際に、OSの「Device Credentials」などの画面が開き、Bluetooth Passkeyの入力を求められることがある。

**固定コード`123456`を入力する。** 教材用の全基板共通値で、Serial Monitorを開いて調べる必要はない。以下のログもBLE開始時と接続時に表示する。

```text
BLE connected
BLE setup pairing code: 123456
```

コードは再起動後も`123456`のまま。固定Passkeyに対応したファームウェアを再Uploadして使用する。すでにペアリング済みなら、入力画面が出ないこともある。

この画面にはルーターのWi-Fiパスワードや、長いWi-Fi接続キーを入力しない。

## 3. 「ESP32のWi-Fi接続」画面

**BLE接続中のESP32をWi-Fiルーターや携帯のテザリングへ接続するための設定**。保存済み機器の選択画面はなく、SSIDとパスワードのフォームだけを表示する。

| 項目・ボタン | 説明・操作 |
|---|---|
| Wi-Fiを検索 | ESP32の周囲にある2.4GHz Wi-Fiを検索する。PC側の現在のSSIDを自動取得する機能ではない |
| SSIDを手入力／履歴・検索結果の一覧 | 「以前接続したSSID」から選ぶか、「Wi-Fiを検索」で周囲のSSIDを選ぶ。「SSIDを手入力」も使える。選択すると入力欄とChrome保存用の識別名を更新し、パスワード欄は空にする |
| SSID（2.4GHz）の欄 | ESP32が接続するネットワーク名。大文字・小文字・空白も含めて正確に指定する |
| SSID直下の`wifi:SSID名`の欄 | ChromeへWi-Fiパスワードを保存するための識別名。SSIDから自動生成され、読み取り専用。ルーターへ送るユーザー名ではない |
| Wi-Fiパスワード | 選んだSSIDのルーター／テザリングのパスワード。教材用固定キーとは別。SSIDを入力・選択し直すとこの欄は空になる |
| パスワードなしのネットワーク | パスワード不要のWi-Fiを使うときだけチェックする。パスワード欄は空になり、入力できなくなる。検索結果がオープンネットワークなら自動でチェックされる |
| ChromeへWi-Fiパスワードの保存を要求する | 接続成功後、ルーターのパスワードを`wifi:SSID名`の識別名でChromeへ保存要求する。固定接続キーは保存しない |
| Wi-Fiへ接続 | SSIDとパスワードをBLE接続中のESP32へ送り、Wi-Fi接続・保存を待ったあと、diagramもWi-Fiの制御接続へ切り替える。機器選択は不要 |
| ESP32の保存済みWi-Fi設定を消去 | ESP32内のSSID・パスワードを消去し、ESP32をルーターから切断する。基板ID・固定接続キー、Chromeの保存項目は残る |

現在の入力制限はSSIDが1～32バイト、パスワードが8～63バイト。パスワード不要の場合はチェック欄で指定する。バイト数は文字数と異なり、日本語などは1文字で複数バイトになる。

2026-10-19追加: Wi-Fiの制御接続まで成功したSSID名だけを、このブラウザーの履歴へ新しい順に最大20件保存する。同じSSIDは重複させず、検索後も履歴を残す。以前の版にはSSID履歴がないため、変更後に接続成功したSSIDから一覧へ追加される。履歴にはパスワードを含めない。検索せず履歴からオープンネットワークを選ぶ場合は「パスワードなし」を指定する。

## 4. 接続の操作手順

1. ESP32を起動し、PC／Androidを同じLANで通信できるWi-Fiへ接続する。
2. diagramの接続ブロックで「接続」を押し、Chromeの機器選択画面から対象ESP32を選ぶ。
3. ブロックが「BLE接続」「状態：接続済み」になったら「Wi-Fi設定／接続」を押す。
4. OSがペアリングコードを要求した場合は、`123456`を入力する。
5. 基板との通信確認が終わるまで待つ。設定画面で機器を選ぶ必要はなく、接続キーの入力も不要。
6. 「以前接続したSSID」から選ぶか、「Wi-Fiを検索」でSSIDを選ぶ。SSIDの手入力も可能。
7. ルーターのパスワードを入力する。Chromeへ保存したい場合は、保存チェックを付ける。
8. **「Wi-Fiへ接続」**を押して待つ。設定・接続の成功後に画面が閉じ、接続ブロックが「Wi-Fi接続」「状態：接続済み」になることを確認する。
9. Chromeが保存確認を表示した場合は、必要な保存項目を承認する。

ESP32はWi-Fi接続とサーバー開始の成功後にSSID・パスワードを保存する。失敗時は以前の保存値を上書きしない。diagramは基板ID・mDNS名・IPなどをBLEから自動取得し、接続中だけ使う。

BLEからWi-Fiへ切り替える際はサーボとIMU通知を一度停止し、Wi-Fi制御接続の確立後にBLEを停止する。IMUBlockがあれば通知を再開する。サーボは自動有効化せず、改めて「90°で有効化」を押す。

## 5. 次回の接続

次回も上記の手順でBLE接続し、「以前接続したSSID」から選んでパスワードを指定し、「Wi-Fiへ接続」を押す。SSIDの手入力も使える。ESP32自体は起動時に保存済みSSID・パスワードでルーターへ接続するが、diagramの接続先は毎回BLEで取得する。図の読込やブロック配置だけでは自動接続しない。接続先はmDNS名を先に試し、失敗時はBLEで取得した現在のIPを試すので、IPの手入力は不要。

ルーター変更、ESP32の保存設定消去、IP変更などで接続できない場合は、BLEから設定・接続先を確認し直す。旧ファームウェアは固定キーに対応しないため、更新してから接続する。

## 6. 保存場所と削除の違い

| 保存場所 | 保存する内容 | 消す操作 |
|---|---|---|
| ESP32の不揮発性メモリ | SSID・Wi-Fiパスワード、基板ID | 「ESP32の保存済みWi-Fi設定を消去」はSSID・パスワードだけを消す。旧版の接続キーは新ファームウェアの起動時に削除する |
| このブラウザーのlocalStorage | `uroa-wifi-ssids-v1`へ接続成功したSSID名の配列だけを最大20件保存する。ESP32の接続先情報と旧版の`uroa-robot-endpoints-v1`は利用しない | ブラウザーのサイトデータ削除でSSID履歴も消える。ESP32内のWi-Fi設定消去では消えない |
| Chromeのパスワードマネージャー | 保存を承認したWi-Fiパスワード（`wifi:SSID名`）。接続キーの新規保存要求は行わない | Chromeのパスワードマネージャーで対象項目を削除する。旧版の`robot:基板ID`は不要だが、自動削除はしない |

Chrome保存のチェックを外しても、ESP32へのWi-Fi設定保存は行う。チェック欄はChromeへのパスワード保存要求だけを制御する。

図のDownload・コピー・JSONとlocalStorageには、Wi-Fiパスワードと接続キーを含めない。固定キーはソースに公開された教材用共通値で、基板ごとの秘密情報ではない。ChromeのWi-Fiパスワード保存・自動入力はChrome側の判断や設定に依存し、チェックだけで保存成功を保証するものではない。

別のURLやChromeプロファイルを使う場合も、BLEから接続先を取得する。

SSID履歴はブラウザー・プロファイル・オリジンごとに保存され、PCとタブレットでは共有しない。保存が利用できない環境では履歴を使わず、手入力と検索を継続する。

## 7. 閉じる・切断・設定変更

「閉じる」またはEscapeは設定画面を閉じ、画面内の入力値とブラウザー側の待機を解除する。保存済み設定は削除しない。ESP32へ送信済みのWi-Fi設定は、画面を閉じてもESP32側で処理が続く場合がある。

BLE接続中に設定画面を開くと、サーボを停止しIMU通知を一時停止する。Wi-Fiへ切り替えず閉じた場合はBLEの通信とIMU通知を再開するが、サーボは自動有効化しない。

ルーターのSSIDやパスワードを変える場合は、接続ブロックの「切断」を押し、BLEから再接続して再設定する。新しいWi-Fi接続に成功すれば保存値を置き換えるため、変更だけなら先に保存済み設定を消す必要はない。

現在はdiagramのタブが非表示になるとBLE／Wi-Fiの制御接続を切断する。別タブへの切り替えやウィンドウの最小化後は、必要に応じて再接続する。Clearや図の読込、ページを離れる操作でも接続を解除する。ESP32は制御接続終了後に復旧用BLEを再開し、再起動時にもBLEを有効にする。

## 8. 表示から次の操作を判断する

| 表示・状況 | 次の操作 |
|---|---|
| SSIDを履歴から選択するか入力し、パスワードを指定して「Wi-Fiへ接続」を押してください。 | SSID・ルーターのパスワードを指定し、「Wi-Fiへ接続」を押す |
| 先に「接続」でESP32へBLE接続してから、Wi-Fi設定を開いてください。 | 接続ブロックの「接続」で対象ESP32へBLE接続してから、「Wi-Fi設定／接続」を押す |
| Wi-Fi設定を開けません。対応するファームウェアとBLE接続を確認してください。 | 対象ESP32のファームウェアとBLE接続を確認する。Wi-Fi接続中ならいったん切断する |
| 教材用の固定接続キーに対応したファームウェアを書き込んでください。 | 対象ESP32へ更新したファームウェアをUploadし、BLEから接続し直す |
| Wi-Fi接続が時間切れ、またはWi-Fi設定に失敗 | 2.4GHzのSSIDとそのパスワードを確認する。ESP32へアンテナが接続されているかも確認する |
| Wi-Fiの応答が途切れました。再接続してください。 | diagramとESP32のネットワーク、別タブへの移動などによる切断を確認し、再接続する |
| Wi-Fi接続中で「Wi-Fi設定／接続」を押せない | 設定を変更する場合は「切断」後にBLEから再接続する |

Wi-Fiの制御接続が成功したらCameraBlockを配置すると画像取得が始まる。Startや他ブロックとの配線は不要。現在の取得ループの追加待ちは0msで、実際の更新間隔は撮影・通信・画像読み込みなどの時間に依存する。

2026-10-19追加: BLE接続の初期化で例外が発生した場合と15秒の接続タイムアウトでは、ChromeのConsoleへ`[BLE] 接続失敗`と`stage`（処理段階）・`name`（エラー名）・`message`（全文）を出す。画面のエラー説明にも処理段階を付ける。機器選択のキャンセルと全体の取消は診断エラーにしない。接続キー・Wi-Fiパスワードはログへ含めない。

PCだけ接続できない場合はdiagramを再読み込みし、F12で開発者ツールのConsoleを開いたまま接続を試す。`[BLE] 接続失敗`のオブジェクトを展開し、3項目を確認する。たとえば`stage`が`GATT接続`ならサービス取得より前で失敗している。ESP32のSerial Monitorの表示と照合して原因を切り分ける。タブレットを接続したままPCから試さない。診断の追加自体はWeb側だけの変更で、ファームウェア再Uploadは不要。
