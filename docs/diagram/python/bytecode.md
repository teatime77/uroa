# ESP32向けPython VMのバイトコード

2026-11-03: [bytecode.ts](../../../diagram/ts/python/bytecode.ts)の`generateAssembly(module: Module): string`が、以下の命令・疑似指示をテキストで生成する。`generateBytecode(module: Module): Uint8Array`は同じ命令列から文字列を含まないバイナリを生成する。BLE送信、ESP32のローダー・VMは未実装。CALL／RETは[実装方針](codex-bytecode-instructions.md)に従ってフレーム管理を含む契約へ拡張したもので、ESP32側に実装済みという意味ではない。

## バイトコードの説明

以下の記述で v は変数名、n は数値、L はラベル。

バイトコードではvとLはアドレスを指すuint16。

vが局所変数ならベースポインタからの相対位置で、大域変数なら大域変数領域の絶対位置。
分岐先Lは所属関数の先頭PCからの相対位置（モジュール本体ではプログラム先頭からの相対位置）、CALL先Lはプログラム先頭からの関数入口の絶対位置。データスタックのベースポインタBPとは区別する。
nはint32またはfloat32。

アセンブリではvとLを名前のまま保持し、バイナリでは数値へ解決する。変数位置は値スタックのスロット単位で、関数内の仮引数はBP+2から、追加の局所変数はその後へ並べる。大域変数は0から割り当てる。命令アドレスは命令列先頭を0とするバイト単位で、ヘッダー・関数表の長さを含めない。

## バイナリ形式version=1

全体を「16バイトのヘッダー → 関数情報（1個8バイト）→ 命令列」の順に置く。複数バイトの数値は全てlittle endian、パディングなし。変数名・関数名・ラベル名・Python原文・行番号・アセンブリコメントは一切含めない。

### ヘッダー

| バイト位置 | 型 | 内容 |
|---|---|---|
| 0 | uint16 | 数値識別子`0xB1C0`（バイト列は`C0 B1`） |
| 2 | uint16 | 形式version。現在は1 |
| 4 | uint16 | 大域変数の個数 |
| 6 | uint16 | 関数情報の個数F |
| 8 | uint32 | 命令列のバイト長C（1〜65536） |
| 12 | uint16 | モジュール本体の開始PC。現在は0 |
| 14 | uint16 | 予約領域。現在は0 |

関数情報はバイト位置16から、命令列は`16 + F * 8`から始まる。全体の長さは`16 + F * 8 + C`。命令列の長さは65536まで許可するためuint32で持ち、実際の命令を指すPCは0〜65535のuint16で表す。大域変数数・関数数・仮引数数・追加の局所変数数はuint16で表現できる範囲とする。局所変数の最終位置も管理領域2個を含めてuint16以内に収める。上限超過は生成時にcharPos付きのRangeErrorとし、切り詰めない。

### 関数情報（1個8バイト）

| レコード内のバイト位置 | 型 | 内容 |
|---|---|---|
| 0 | uint16 | 関数入口の絶対PC |
| 2 | uint16 | その関数の命令列のバイト長 |
| 4 | uint16 | 仮引数の個数 |
| 6 | uint16 | 仮引数以外の局所変数の個数 |

関数情報はdefの順に並び、関数本体もその順でモジュール本体の後へ置く。関数名や引数名の領域は持たない。CALLのオペランドは関数番号ではなく入口PCであり、VMは入口PCに一致する関数情報からフレームの大きさを得る。

モジュール本体の範囲はPC=0から最初の関数の直前まで。関数がなければ命令列全体がモジュール本体となる。各関数の範囲は関数情報の入口PCと長さから決める。分岐命令は、その範囲の先頭PCにuint16のオフセットを加えて実際のPCを得る。後方への分岐も負数を使わず、関数先頭からの位置を指定する。

### 命令番号とエンコード

opcodeはuint8で、オペランドは直後へ置く。長さはopcodeを含む。`BytecodeOpcode`としてTypeScriptからも公開する。

| opcode（16進） | 命令 | オペランド | 長さ |
|---|---|---|---|
| 01 | LOAD_L | uint16: BPからのスロット位置 | 3 |
| 02 | LOAD_G | uint16: 大域変数スロット番号 | 3 |
| 03 | PUSH_INT | int32 | 5 |
| 04 | PUSH_FLOAT | IEEE 754 float32 | 5 |
| 05 | STORE_L | uint16: BPからのスロット位置 | 3 |
| 06 | STORE_G | uint16: 大域変数スロット番号 | 3 |
| 07 | JUMP | uint16: 所属範囲内のバイト位置 | 3 |
| 08 | JUMP_IF_FALSE | uint16: 所属範囲内のバイト位置 | 3 |
| 09 | JUMP_IF_TRUE | uint16: 所属範囲内のバイト位置 | 3 |
| 0A | ADD | なし | 1 |
| 0B | SUB | なし | 1 |
| 0C | MUL | なし | 1 |
| 0D | DIV | なし | 1 |
| 0E | EQ | なし | 1 |
| 0F | NE | なし | 1 |
| 10 | LT | なし | 1 |
| 11 | LE | なし | 1 |
| 12 | GT | なし | 1 |
| 13 | GE | なし | 1 |
| 14 | CALL | uint16: 関数入口の絶対PC | 3 |
| 15 | RET | なし | 1 |
| 16 | PUSH_NONE | なし | 1 |
| 17 | POP | なし | 1 |
| 18 | HALT | なし | 1 |

例えば、最初の大域変数への`x = 1`は、命令列だけなら`03 01 00 00 00 06 00 00 18`となる。PUSH_INT 1、STORE_G 0、HALTの順で、xという名前は残らない。

### ESP32で受け取る際の契約

受信側ローダーは、識別子・version・予約領域・開始PC・長さの一致と上限、関数範囲の順序・連続性、各命令の番号と長さを全件検証してから実行する。CALL先は関数入口への一致、分岐先は所属範囲内の命令先頭への一致、変数位置は大域変数数または関数フレームの範囲内であることを検査する。局所変数のスロット0・1は管理用なのでLOAD_L／STORE_Lの対象にせず、モジュール本体からの局所変数アクセスも拒否する。整数・浮動小数点の読み出しは非整列アドレスを許す方法で行う。

実行時にはスタックの上限・下限と未初期化値も検査する。これらのローダー・VM処理、BLEのCharacteristic・分割転送・完了確認は今回実装していない。このバイナリを既存のサーボ制御やDeviceInfoのCharacteristicへ送る形式ではない。

## 各命令の動作

### LOAD_L, LOAD_G
```asm
LOAD_L v
LOAD_G v
```
局所変数(LOAD_L)または大域変数(LOAD_G)の変数vをスタックにpushする。
未初期化の変数を読む場合は実行時エラーにする。

### PUSH_INT

```asm
PUSH_INT n
```
整数nをスタックにpushする。

### PUSH_FLOAT

```asm
PUSH_FLOAT n
```
浮動小数点数nをスタックにpushする。生成器は有限のfloat32へ変換可能か検査する。float32への丸め・アンダーフローによる0への変換は許可する。

### PUSH_NONE, POP

```asm
PUSH_NONE
POP
```

PUSH_NONEはNoneを1個pushする。Noneは0および未初期化の印と区別する。POPはトップの値を1個捨てる。式文は呼出しの戻り値等をPOPで捨て、一時値を残さない。

### STORE_L, STORE_G

```asm
STORE_L v
STORE_G v
```
スタックから値をpopして局所変数(STORE_L)または大域変数(STORE_G)の変数vに代入する。

### JUMP

```asm
JUMP L
```
所属関数の先頭PCにLを加えた位置をpcにセットする。モジュール本体の基準はプログラム先頭。

### JUMP_IF_FALSE

```asm
JUMP_IF_FALSE L
```
条件を1個popし、偽ならJUMPと同じ基準でLへ分岐する。数値0とNoneは偽、それ以外の数値は真とする。True／Falseは生成時に整数1／0へ変換する数値中心のサブセットで、Pythonのbool型を区別しない。

### JUMP_IF_TRUE

```asm
JUMP_IF_TRUE L
```
条件を1個popし、真ならJUMPと同じ基準でLへ分岐する。現行生成器はこの命令を使わない。

### ADD, SUB, MUL, DIV

```asm
ADD
SUB
MUL
DIV
```
右辺、左辺の順に2個popして、`左辺 op 右辺`の結果を1個pushする。式の生成は左辺、右辺の順に行う。DIVは整数同士でもPythonの`/`に相当する除算とする。四則演算の対象は数値で、None等への演算は実行時エラーにする。整数演算のオーバーフローや0除算の詳細はVM実装時に確定する。

### EQ, NE, LT, LE, GT, GE

```asm
EQ
NE
LT
LE
GT
GE
```
右辺、左辺の順に2個popし、`左辺 op 右辺`が真なら整数1、偽なら0をpushする。数値は数値として比較する。None同士のEQは1、Noneと数値のEQは0、NEはその逆。Noneを含む大小比較は実行時エラーとする。

### CALL

```asm
CALL L
```
呼出し元は引数を左から右へ評価して積む。CALLは関数情報に従ってスタックフレームを作り、pcをLへ移す。戻り先PCはCALLの次の命令。

SPを「次にpushするスロットの位置」とする。引数n個を積んだ直後のSPをSとすると、新しいBPは`S - n`。引数を2スロット上へずらし、BP+0へ戻り先PC、BP+1へ旧BPを置く。仮引数はBP+2以降、追加の局所変数m個はBP+2+n以降へ置き、SPを`BP + 2 + n + m`にする。追加の局所変数は未初期化の印にする。BPより下にある呼出し元の一時値は保持する。

### RET

```asm
RET
```
トップの戻り値を1個退避し、現在のBP+0とBP+1から戻り先PCと旧BPを読む。SPを現在のBPへ戻してフレーム全体（引数を含む）を解放し、PCと旧BPを復元する。最後に戻り値を1個pushする。値のないreturnと関数末尾ではPUSH_NONE・RETを生成する。

### HALT

```asm
HALT
```

モジュール本体を終了する。関数本体はHALTの後に配置し、CALLでのみ入る。

## アセンブリの疑似指示

```asm
.globals 1
.function add 2 1
```

`.globals`は大域変数の個数、`.function 名前 引数個数 追加の局所変数個数`は関数情報を表す。関数名と同名のラベルを入口とする。疑似指示は実行命令ではなく、命令列のPCを進めない。変数名からスロット番号への対応は生成器内部で保持しており、現在のテキスト出力だけを再読込するアセンブラは実装していない。

`parsePython()`は元のPythonソースを`Module.source`へ保持する。生成器は命令・ラベルの`charPos`から元の行を調べ、`; 行番号: Pythonの原文`を直前に出力する。同じ行に対応する連続した命令ではコメントをまとめる。行番号は1始まりで、元の字下げとコメントを保持し、LF・CRLF・CRの改行に対応する。HALTと暗黙の関数末尾は`; 自動生成`で区別する。疑似指示には行コメントを付けない。元ソースを持たない手動作成のModule等では、従来の命令のみを出力する。

## 変数の領域確保

Pythonには変数宣言がないので、ソースコードで代入されている変数を探して、その変数の領域を確保する。

関数の引数も確保する。forのループ変数への対応は後の実装とする。

大域変数では大域変数用の領域に確保し、関数内の局所変数はスタックに領域を確保する。

関数内のif・whileやreturn以降も事前走査する。同名は1領域にまとめ、ブロックごとの領域は作らない。代入先に現れた名前は関数全体で局所変数、その他の参照は大域変数となる。大域変数も未初期化の印で確保する。実際のフレーム確保・未初期化検査・戻り値の受渡しは、この契約に従う将来のVMの責務。

## 使用例と生成範囲

```typescript
import { parsePython } from "./python/parser.js";
import { generateAssembly, generateBytecode } from "./python/bytecode.js";

const module = parsePython("def calc(a, b, c):\n    return a * (b + c)\nresult = calc(2, 3, 4)\n");
const assembly = generateAssembly(module);
const bytecode = generateBytecode(module); // ヘッダーを含む転送用のUint8Array
```

上の例は以下の形式を生成する。

```asm
.globals 1
.function calc 3 0
; 3: result = calc(2, 3, 4)
PUSH_INT 2
PUSH_INT 3
PUSH_INT 4
CALL calc
STORE_G result
; 自動生成
HALT
; 1: def calc(a, b, c):
calc:
; 2:     return a * (b + c)
LOAD_L a
LOAD_L b
LOAD_L c
ADD
MUL
RET
; 自動生成
PUSH_NONE
RET
```

末尾のPUSH_NONE・RETは明示returnがない経路用に常に付けるため、この例では到達しない。

バイナリ生成はこのアセンブリ文字列を再解析せず、共通の内部命令列・変数表から行う。1回目に命令長からラベルのPCを決め、2回目に変数位置・分岐先・CALL先を数値化して書き込む。アセンブリの原文コメントは従来どおり出力されるが、バイナリには入らない。開発用の`testPython()`は、従来のアセンブリに加え、生成バイト数と16進表示も出力する。16進表示は人向けの文字列であり、ESP32へ渡す本体はUint8Arrayとする。

対応対象は単一変数の代入と四則の複合代入、四則・単項符号・単独の比較、if／elif／else、while・break・continue・pass、モジュール先頭に連続するdef、静的な位置引数呼出し・再帰・return。生成ラベルは`$`で始め、Pythonの関数名との衝突を避ける。文字列・属性・添字・for・import・論理演算・連鎖比較・関数値・入れ子のdef等はcharPos付きのSyntaxErrorで拒否する。定義後の変数や引数と関数の同名使用も拒否し、関数名の束縛変更は扱わない。
