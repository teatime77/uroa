# PIDBlock（初版はP制御）

更新日: 2026-11-01。

[PIDBlock](../../diagram/ts/control/pid.ts)はFunctionBlockとして、IMUValueの加速度から2個のモータの速度を計算する。ツールボックスのIMUの直後に「PID」のアイコンを置く。初版ではP項だけを実装し、Ki・Kdは数値入力とJSON保存に対応するが計算には使わない。ESP32への通信遅延の補償、積分・微分、フィルターは実装しない。

## 接続と操作

1. BLE接続、IMU、PID、2個のServoMotorBlockを配置する。
2. IMUのStruct出力をPIDの`imu`入力へ接続する。接続元は1個に限定する。
3. PIDの`M1`・`M2`を、それぞれのServoMotorBlockのNumberPort入力へ接続する。
4. 各ServoMotorBlockを速度モードにし、別々のCHを選び、「0%で有効化」を明示的に操作する。PIDは有効化やCH選択を行わない。
5. Kp・Ki・Kd、各モータの停止範囲の最小値・最大値（%）を設定する。既定値はKp=1、ほかは0。
6. 機体を基準姿勢にして全体のStartを押す。制御開始後の最初の新しいIMU計測を垂直基準とし、その後の計測ごとに速度を出力する。
7. 全体のStopで終了する。再度Startすると垂直基準を取り直す。

制御中はActionチェーン終了後もStartを実行中に保ち、Stopを受け付ける。PIDの`run()`は連続制御を開始して戻り、[index.ts](../../diagram/ts/index.ts)がActionチェーンの後で`waitUntilStopped()`を待つ。後続のActionは最初のIMU計測の完了を待たない。

有効な設定変更は制御中にも反映する。不正な設定、入力の未取得・消失、入力の接続変更、全体Stop、タブ非表示、pagehide、削除・Clear・図読込・破棄では制御を停止する。中断後はStartによる明示的な再開が必要。通知が途絶えたまま値が残る場合のタイムアウト監視は初版に含めない。

## 傾きとP出力

加速度はIMUBlockの出力するm/s²を使う。角度の単位は度。

```text
tilt = atan2(acc.y, hypot(acc.x, acc.z)) × 180 / π
referenceTilt = 制御開始後の最初のtilt
error = referenceTilt − tilt
p = Kp × error
```

Kpの単位は%/度で、負の値も設定できる。角度は−90～90度の範囲で、加速度Yの重力方向成分から求める。ジャイロ値・Telemetry時刻は初版では使わない。全加速度が0の場合は計算を中断する。

2個のモータには同じ符号のP出力を使い、それぞれの停止範囲で個別に補正する。モータごとの回転方向反転は初版に含めない。

## 停止範囲の補正

各モータについて、最小値`min`・最大値`max`は−100～100%の範囲で`min <= max`とする。P出力を次のように補正し、最後に−100～100%へ制限する。

| P出力 | 補正後の速度 |
|---|---|
| 正 | `max + p` |
| 負 | `min + p` |
| 0 | `(min + max) / 2` |

例: 停止範囲−5～3%なら、P出力10で13%、−10で−15%、0で−1%となる。IMU計測待ち・制御終了・入力異常の際も、制御が動作中なら各停止範囲の中央を出力する。全体Stopは既存のサーボSTOPも要求し、PWMを無効化する。

## JSON・コピー・後片付け

通常のポート情報に加え、`kp`・`ki`・`kd`・`motor1StopMin`・`motor1StopMax`・`motor2StopMin`・`motor2StopMax`を保存する。設定の欠落は既定値で補い、非有限値や不正な停止範囲を拒否する。入力欄が不正な状態では保存を拒否する。

コピーも同じ設定を移す。基準角、計測値、現在速度、制御中の状態は保存・コピーしない。読込やコピーだけで制御を開始しない。

削除時は制御を停止し、停止・接続変更の購読を解除し、DOMイベントと設定欄を除去して全ポートの接続を解除する。

検証範囲と結果は[ビルドと回帰テスト](../build-and-test.md)を参照する。実BLE／Wi-Fi、モータの方向・停止範囲・速度、機体の安定性は実機確認が必要。
